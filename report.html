Giải thích:

  • Context Block: Sử dụng get_user_context để lấy Context Block do Zep tổng hợp (chứa User Summary và Facts) dựa trên relevance của thread. Đây là bộ nhớ cốt lõi mang tính tóm tắt dài hạn.
  • User Isolation: Mọi truy vấn đều phải map qua thread_id (gắn với user_id), đảm bảo Agent không bị rò rỉ (leak) dữ liệu từ người dùng khác (privacy).
  • Recency: Context Block của Zep tự động xử lý recency (tính mới) cho các facts (ví dụ user đổi từ Python sang TypeScript) giúp thu thập thông tin nhất quán và cập nhật.
  • Edges Search: Tìm kiếm thêm các quan hệ (edges) với limit cao (=20) vì các task/open loops (deadline) đôi khi không lọt vào context block tóm tắt mà nằm rải rác dưới dạng node/edge.

def retrieve_episodic(self, user_id: str, query: str) -> str:

        limit=5
    )
    return render_graph_search(results, episode_char_cap=200)

Giải thích:

  • Scope: Tìm kiếm bằng scope="episodes" để truy cập lại raw messages/documents (các trajectory đã lưu) với đầy đủ context thực tế lúc xảy ra.
  • Limit & Capping: Đặt limit=5 và episode_char_cap=200 để tránh tình trạng tràn bộ nhớ do một message quá dài (verbose) có thể đẩy các reflections quan trọng ra khỏi token budget (3%).
  • Provenance: Đảm bảo Agent có bằng chứng rõ ràng (provenance) để tự tin trả lời thay vì ảo giác (hallucination) dựa trên kiến thức base model.
Task 3/4

Semantic Memory (Tri thức Domain)

Mục tiêu: Truy xuất các thông tin, quy tắc chung của hệ thống không phụ thuộc vào cá nhân (ví dụ: tài liệu API, rule thanh toán).

Logic Code:

def retrieve_semantic(self, graph_id: str, query: str) -> str:
    capped_query = cap_query(query)
    chunks = []
    try:
        results = self.client.graph.search(
            graph_id=graph_id,
            query=capped_query,
            scope="episodes",
            limit=8
        )
        seen = set()
        for ep in getattr(results, "episodes", []) or []:
            content = getattr(ep, "content", "")
            if not content: continue
            
            # Khử trùng lặp giữa bản ghi JSON và Text
            if content.strip().startswith('{"id":'):
                try:
                    obj = json.loads(content)
                    content = obj.get("summary", content)
                except Exception:
                    pass
            if content not in seen:
                seen.add(content)
                chunks.append(f"EPISODE: {content}")
    except Exception:
        pass
        
    try:
        results = self.client.graph.search(
            graph_id=graph_id, query=capped_query, scope="nodes", limit=3
        )
        chunks.append(render_graph_search(results))
    except Exception:
        pass
        
    return join_nonempty(chunks)

Giải thích:

  • Standalone Graph: Tìm kiếm trên một knowledge graph độc lập (graph_id) thay vì user_id để khai thác tri thức chung toàn domain.
  • Giữ Literal Markers: Ưu tiên scope="episodes" thay vì "auto" vì Zep's entity extractor thường lược bỏ đi các mã code nguyên bản (ví dụ PAYMENT-RULE-3, BUDGET-10-4-3-3) mà lab cần.
  • Tối ưu Budget (Deduplication): Dữ liệu knowledge base được đẩy vào Zep dưới dạng 2 kiểu payload: JSON và Text. Đoạn mã trên nhận diện JSON và trích xuất trường summary, sau đó khử trùng lặp (set seen) để tránh lãng phí token budget (cực kỳ nhạy cảm cho semantic ở mức 3%), giúp lấy đủ tài liệu mà không bị cắt xén đoạn chứa marker.

Giải thích:

  • Token Budgeting: Cắt tỉa (trimming) text của từng layer theo ngân sách cho phép (Short-term: 10%, Long-term: 4%, Episodic: 3%, Semantic: 3%).
  • Thứ tự ưu tiên (Priority): Agent nhận context theo trình tự hợp lý từ gần đến xa, từ cá nhân đến chung:
    1. Short-term (cuộc trò chuyện hiện tại)
    2. Long-term (thói quen, fact cá nhân)
    3. Episodic (trải nghiệm quá khứ)
    4. Semantic (kiến thức chung).
  • Ngăn chặn tràn bộ nhớ (Context Overflow): Các bộ nhớ phụ (như semantic/episodic) bị cắt xén từ dưới lên nếu vượt budget, đảm bảo không đẩy các token quan trọng nhất (short-term & long-term) ra khỏi cửa sổ ngữ cảnh.
